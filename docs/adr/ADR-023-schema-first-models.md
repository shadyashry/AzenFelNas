# ADR-023 · Schema-first models with hand-written serializers, validated by fixtures

- **Status:** `[DECIDED]`
- **Source:** `DESIGN.md` §4 ADR-023 (binding index). This file is the long-form record; where they differ, `DESIGN.md` wins (ADR-000).

## Context

Stub generated in slice S01 from the `DESIGN.md` §4 index entry. Long-form context is added when this ADR is next amended.

## Decision

JSON Schema in `schemas/` is the contract. Dart: hand-written `freezed` + `json_serializable`; Kotlin: `kotlinx.serialization`; Swift: `Codable`; Go: generated by `go-jsonschema`. CI round-trips `schemas/fixtures/*.json` through every language and validates with `ajv`.

## Trade-offs

- **Win:** idiomatic code everywhere.
- **Lose:** four model sets kept in sync (fixtures catch drift).

## Amendment proposed in S02 (2026-10-21) — pending Architect approval (§23.3)

**Go models are hand-written, not generated by go-jsonschema.** Recorded as `DESIGN.md` §15 D24; the §4 index text is unchanged until the Architect approves.

Evidence: go-jsonschema 0.24.1 was run on the three Go-consumed schemas in S02. Its `prayer_profile.v1` model failed the ADR-023 fixture round-trip: it dropped every explicit `null` the schema requires (`effectiveTo`, `scope.polygonsRef`, `evidence.holdoutReport`, `evidence.benchmarkReportId`, `approvals.*`) and encoded the `rounding` overrides under a literal `"AdditionalProperties"` key. It also typed every `const` and `oneOf` member as `interface{}` (including the TUF `signed` document gsctl must sign) and added two runtime dependencies (`go-jsonschema/pkg/types`, `go-viper/mapstructure/v2`). The hand-written models in `tools/gsctl/internal/schema/{profile,tuf}` and `services/control-plane/internal/schema/telemetry` are typed sealed unions with strict decoding, round-trip every valid fixture, add no dependency, and match how Dart, Kotlin and Swift models are already written.

Language matrix (§15 D24): each language models the schemas it produces or consumes — see `schemas/README.md`. The fixtures are the cross-language contract; ajv-cli validates them in `ci-schemas`.

## Python models (slice S03, 2026-10-21)

As §17.6 requires, the lab's models are pydantic v2 classes **generated** from `schemas/`. `lab/scripts/gen_models.sh` runs datamodel-code-generator; the output is committed under `lab/src/dm_lab/schema/`, and `ci-lab` fails if regeneration changes it (§15 D27). Every valid fixture of the seven schemas the lab models round-trips through them (`lab/tests/test_schema_models.py`).

Invalid fixtures that need a JSON Schema conditional (`if/then/else`) are listed in that test, because pydantic does not model conditionals. ajv still rejects them, and the comparator treats such shapes as mismatches.

S03 adds six schemas, with fixtures: `bench_request`, `bench_failure`, `benchmark_cities`, `lab_reference`, `discrepancy_report`, `pipeline_manifest`. In the Dart engine, `bench_request` and `bench_failure` will be modelled when the bench CLI lands (S06).
