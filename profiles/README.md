# profiles/

Prayer profiles are **data** (DESIGN.md §0.2 rule 1, §6.5, ADR-007, ADR-008). Each file is a `prayer_profile.v1` document (Appendix A, `schemas/prayer_profile.v1.schema.json`) in YAML: `profiles/<iso2|engine>/<profileId>.yaml`. CODEOWNERS for this directory are the accuracy lead and the Sharia reviewer (REQ-GOV-002).

## Seed profiles (slice S07, Appendix E)

All four are `DRAFT_UNVERIFIED`. Their values are **illustrative** until evidence and approvals exist, and they load on `dev` and `lab` only: `ProfileLoadPolicy` refuses `DRAFT_UNVERIFIED` and `CANDIDATE` profiles on `beta` and `production`.

Where DESIGN.md gives no value, the seed carries an **engineering default** recorded in §15 D50, never a recalled or invented number:
- rule values: the `engine.default` value;
- the high-latitude chain: the §6.5 illustration;
- authority type: `GOVERNMENT`;
- effective date: the §6.5 example's.

The Sharia board and the accuracy lead replace them through a profile-change PR with evidence.

## Checks

- `schemas/tools/validate_fixtures.sh` validates every `profiles/**/*.yaml` against Appendix A (`ci-schemas`).
- `go run ./tools/gsctl validate -channel <channel>` compiles the set into the `profiles.json` package payload and applies the governance and channel gates. `profiles-gate` runs it, and `gsctl build` signs nothing that fails it (DESIGN.md §15 D60, D61).
- `gsctl check-change` (in `profiles-gate`) refuses a PR that changes an angle of an existing profile together with tz/coordinate data, such as reference points, tz or polygon pipelines, or benchmark coordinates (§9.2, §15 D64). Put such changes in separate PRs.
- `packages/geo_salah_profiles/test/seed_profiles_test.dart` parses and validates each seed, checks that the set does not overlap, and calculates every benchmark city of the profile's scope (the S07 done-test).
- `packages/geo_salah_core/bench/profiles/engine.default.json` is the compiled JSON of `engine/engine.default.yaml` that the engine bench reads. It is regenerated by `dart run geo_salah_profiles:sync_bench_profiles` and checked fresh by a test.
